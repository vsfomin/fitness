# Инструкция для AI-агента

Это личное приложение тренировок пользователя. Общение и интерфейс — на русском. Сначала прочитай `README.md`, `CLAUDE.md`, `program.md` и конец `log.md`.

## Быстрый старт

- Рабочая папка: корень этого репозитория.
- Запуск: `docker compose up -d --build app`.
- Проверка: `curl http://127.0.0.1:18080/healthz`, затем мобильный браузерный прогон.
- Постоянный публичный адрес: `https://rosy-river-0106.a.tuna.free`; фоновая служба Tuna управляется `tuna service ... --name=fitness` и не требует открытого терминала.
- Основной исходник: `gym.html`; не переписывай приложение на другой фреймворк без запроса.
- Автономное хранилище: `server.js` + `web-adapter.js`. Сохрани совместимость существующего формата документов.

## Данные — не потерять

- Актуальные данные: `data/db` и `data/assets`; они синхронизируются в приватный GitHub вместе с кодом.
- Не удаляй и не перезаписывай исторические записи. Проверяй сохранение тестовым документом и удаляй только его.
- Не встраивай `data`, `tools/db`, личные заметки или фото в публичный Docker-образ.
- Публичный образ: `fomik2/fitness:latest`; в нём только код.
- Изменения программы действуют только вперёд. Прошлые тренировки и сохранённый в них план не пересчитывать.

## Проверки после изменений

```bash
./tools/extract.sh
(cd tools && node t16.js 23)
node --check server.js
node --check web-adapter.js
docker compose up -d --build app
```

Проверь основные вкладки в мобильном размере и реальную запись/чтение/удаление тестового документа через API. Существующие предупреждения `t16` не скрывай; исправляй только если задача относится к прогрессии.

После проверенных изменений выполни `./tools/cloud_sync.sh`. Для выпуска образа дополнительно: `docker build -t fomik2/fitness:latest . && docker push fomik2/fitness:latest`.
